## Tests (`db.int.test.ts`)
- Connected to its own database: `current_database()` equals the generated `test_<32 hex>` name.
- Started from the migrated template: `citext` is installed, and there's 1 row in `drizzle.__drizzle_migrations`.
- The real `ping()` resolves, and `/health/ready` returns 200 through `createApp` with the real ping.
- `resetDb`:
  - It empties a scratch `citext` table but keeps the migrations table.
  - The next test sees 0 rows, even though the previous test inserted one after resetting. This proves `beforeEach` runs.
  - The scratch table is then dropped.

## Decisions & trade-offs
- **Denied three more install scripts** (`cpu-features`, `ssh2`, `protobufjs`), all coming from dockerode.
  - `ssh2` and `cpu-features` only build optional native code, used for Docker over SSH.
  - `protobufjs` runs a version check.
  - Testcontainers works without them, as the run shows.
- **SQL injection safety:**
  - Table names are quoted with `sql.identifier`.
  - The per-file database name is generated by us, not user input, and is interpolated into admin statements only.
- **Separate admin connection for each create or drop.** It's short-lived, and it isn't pooled with the file's own handle, so `DROP … WITH (FORCE)` doesn't interfere with it.
- **`test/` lives outside `src/`.** Test infrastructure stays out of the app tree. `tsconfig` includes it, so it's typechecked and linted.

## Deviations from plan
- **No "two files see different DBs" test.** There's only one integration file so far. The isolation guarantee is that each file's database is unique (`test_<uuid>`) and the first test asserts it. A second file will exist naturally once 3.x adds repository tests.
- **I didn't stop Colima for the "no Docker" check.** I pointed `DOCKER_HOST` at a missing socket instead, which has the same effect for the tests without stopping your other projects' containers. Colima had stopped on its own before this task (that was the first integration error), so I restarted it and the Compose Postgres. Both are running.
